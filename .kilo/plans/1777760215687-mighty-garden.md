## 2. Defect Documentation

For each defect, produce:

### 2.1 Missing "Add Item" Functionality
- **Expected:** UI provides a button to add new rows dynamically; each row contains item selector, physical qty, unit cost.
- **Actual:** Rows are pre-populated from `products` list; no way to add items not currently loaded.
- **Root cause hypothesis:** The dialog iterates over `products.map()` without a dynamic row state. No "Add Row" button exists.
- **Impact:** Users cannot reconcile items that are not in the pre-loaded product list (e.g., new stock items).

### 2.2 "Save All Changes" Process Failure
- **Expected:** Save button triggers batch API call; all rows persist; success toast shown; modal closes.
- **Actual:** Save may silently fail, throw uncaught error, or leave UI in loading state.
- **Investigation points:**
  - Does the `for...of` loop in the save handler continue after one failure?
  - Are `await db.query()` calls using correct parameter binding for all updates?
  - Does the backend endpoint return an error that the frontend fails to parse?
  - Is there a missing `await` causing the modal to close before completion?

### 2.3 Session/UI Error — Modal Not Closing
- **Expected:** After successful save, modal dismisses and state resets.
- **Actual:** Modal remains open; UI appears hung; user forced to refresh.
- **Investigation points:**
  - Is `setShowBatchReconDialog(false)` being called in both success and error paths?
  - Could an unhandled promise rejection prevent the finally block from running?
  - Is the `loadData()` call causing a state update after component unmount?

## 3. Technical Requirements for Fix

### 3.1 Add Item — Dynamic Row Feature
- Add "Add Item" button above table that opens an item selector (product dropdown with search)
- Support selecting a product from `products` list (or from API if not in current list)
- Insert new row into `batchData` state with default physicalQty = 0, costPrice = product.cost_price
- Allow removing rows via a trash icon per row
- Ensure `Save All` sends all rows, including newly added ones
- Validate that each row has a valid product_id before enabling Save

### 3.2 Save All — Atomic Transaction & Robust Error Handling
- Frontend:
  - Use a single `Promise.all()` or sequential `for...of` with proper error aggregation
  - Show progress indicator; prevent double-clicks with `disabled` state
  - On failure, display detailed error description from backend; DO NOT close modal automatically on partial failure
  - On complete success, call `setShowBatchReconDialog(false)` and `loadData()`
- Backend (`POST /api/inventory/batch-reconcile`):
  - Wrap entire loop in a single DB transaction (BEGIN…COMMIT/ROLLBACK)
  - Validate each item: product exists, physical_qty numeric, cost_price positive
  - Return partial-success or all-or-nothing based on business rule (recommend all-or-nothing for integrity)
  - Respond with `{ ok: true, message: '...', results: [...] }` or `{ ok: false, error: string }`

### 3.3 Modal Close & State Reset
- Ensure `setShowBatchReconDialog(false)` is called in:
  - Success handler after toast
  - Cancel button (already present)
  - Error handler (optional: keep modal open to allow corrections, but provide "Close" button)
- Also reset `setBatchData({})` on close
- Add cleanup `useEffect` to abort pending operations if component unmounts during save

### 3.4 Additional Safeguards
- Add loading state: `isSaving` boolean; disable Save button while saving
- Show confirmation dialog if user tries to close while there are unsaved changes
- Log all errors to console with full stack for debugging
